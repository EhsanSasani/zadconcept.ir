# محصولات سفارشی: فروش هنگام ثبت و نگهداری پیام تلگرام

مبنا: کد محلی 72bcbd8 و کد VPS معادل 0d4b1e2.

- ثبت جدید سفارشی در پنل فلوریست، دفتر مدیریتی یا ورودی تلگرام از ابتدا SOLD است؛ زمان فروش برابر زمان تولید ثبت می‌شود.
- ارسال موجود پنل فلوریست به گروه سفارشی ادامه دارد؛ SOLD بودن مانع انتشار نمی‌شود.
- سفارشی در کاتالوگ عمومی ایجاد نمی‌شود.
- هیچ پیام سفارشی از طریق صف RETIRE حذف یا تغییر کپشن نمی‌شود، حتی هنگام حذف مدیریتی رکورد. حذف مدیریتی همچنان رکورد را در پنل پنهان و سابقه را حفظ می‌کند.
- کارهای قدیمی RETIRE سفارشی با نتیجه custom_preserved بسته می‌شوند، بدون تماس شبکه. پیام‌هایی که قبلاً حذف شده‌اند بازسازی نمی‌شوند.
- وضعیت رکوردهای قبلی تغییر نمی‌کند. ثبت دستی سفارشی در داشبورد همچنان فقط در دفتر تولید ثبت می‌شود؛ این پچ مسیر ارسال جدیدی برای آن ایجاد نمی‌کند.
- مسیر آماده‌ارسال و تأخیر ۴۵ دقیقه‌ای آن، Worker و اعلان خصوصی تغییری ندارند.
- مهاجرت یا تغییر دادهٔ انبوه لازم نیست.

## اعمال در local

```powershell
git apply --check .\zad-studio-custom-sold-preserved.patch
git apply .\zad-studio-custom-sold-preserved.patch
python manage.py check
python manage.py test main.tests.test_studio_publishing main.tests.test_studio_operations main.tests.test_studio_reconciliation
git diff --check
```

## استقرار بعد از تست محلی

از وضعیت تمیز و نسخهٔ فعلی پشتیبان بگیرید. Worker ارسال‌ها را قبل از اعمال متوقف کنید تا حذف قدیمی هم‌زمان اجرا نشود. سپس پچ را بررسی و اعمال کنید، Django check را اجرا و هر دو سرویس را دوباره راه‌اندازی کنید. اجرای migrate و collectstatic برای این پچ لازم نیست. فایل env، دیتابیس و رسانه را جایگزین نکنید.
