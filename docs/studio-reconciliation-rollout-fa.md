# ادغام اصلاحات Studio — ۲ اکتبر ۲۰۲۶

این نسخه، اصلاحات ایمنی موجود در commit
`5821425deba27df654abe4c7e3b077b973767427` را حفظ می‌کند و اصلاحات عملیاتی
ادامهٔ گفتگو را به همان کد اضافه می‌کند. پچ local از همین commit ساخته شده است؛
پچ ایمنی بزرگ قبلی نباید دوباره روی local اعمال شود.

## رفتار نهایی

- محصول فروخته‌شده یا کشیده‌شده بلافاصله از موجودی سایت خارج می‌شود. حذف پیام
  خروجی آن در گروه آماده‌ها یا سفارشی‌ها، ۴۵ دقیقه پس از ثبت وضعیت انجام می‌شود.
  تکرار همان وضعیت، این مهلت را از نو شروع نمی‌کند.
- حذف مدیریتی، کارنامهٔ فلوریست و کاتالوگ عمومی را بلافاصله به‌روز می‌کند و
  درخواست حذف پیام را بدون مهلت ۴۵ دقیقه‌ای به صف می‌فرستد. علت حذف، عکس و
  سابقهٔ مدیریتی حفظ می‌شوند. محدودیت نرخ تلگرام همچنان رعایت می‌شود.
- صف حذفِ قدیمی با زمان اجرای فوری، هنگام پردازش دوباره با زمان واقعی فروش یا
  خروج سنجیده می‌شود. تلاش دوبارهٔ دستی نیز مهلت ۴۵ دقیقه‌ای را دور نمی‌زند.
- حذف پیامی که قبلاً حذف شده است موفق محسوب می‌شود؛ عکس تازه‌ای برای آن منتشر نمی‌شود.
  مسیر موجودِ اصلاح کپشن برای پیام‌های غیرقابل‌حذف حفظ شده است.
- در فرم ثبت فلوریست، هیچ نوع تولیدی از ابتدا انتخاب نشده است. انتخاب
  «آماده روز» یا «سفارش اختصاصی» اجباری است؛ بدون انتخاب، محصول و صف ارسال
  ساخته نمی‌شوند. فلوریست سازنده نیز باید از بین همکاران فعال انتخاب شود.
- قیمت هنگام تایپ با جداکنندهٔ هزارگان نمایش داده می‌شود. ارقام فارسی و عربی
  پذیرفته می‌شوند و اصلاح وسط عدد، محل نشانگر تایپ را حفظ می‌کند. پیش‌نویس، عکس
  و شناسهٔ جلوگیری از ثبت تکراری در مسیر بازیابی حفظ می‌شوند.
- اعلان خصوصی مدیر به‌صورت پیش‌فرض خاموش است. باقی‌ماندن شناسهٔ مدیر در `.env`
  باعث ارسال نمی‌شود. هیچ اعلان خصوصی تازه‌ای صف نمی‌شود؛ صف‌های قدیمی پردازش
  یا بازیابی نمی‌شوند و سابقهٔ آن‌ها در دیتابیس حفظ می‌شود. صفحهٔ تاریخچه فقط
  برای مدیر قابل‌مشاهده است و اقدام ارسال دوباره ندارد.

خاموش‌بودن اعلان خصوصی با تنظیم زیر کنترل می‌شود:

```dotenv
STUDIO_ADMIN_NOTIFICATIONS_ENABLED=false
```

نبود این متغیر نیز به معنی خاموش‌بودن است. اگر متغیر از قبل صریحاً `true` شده
باشد، پیش از بارگذاری نسخهٔ جدید باید `false` شود. پاک‌کردن تاریخچه یا شناسهٔ
مدیر برای این تغییر لازم نیست.

## محدودهٔ تغییر

فایل اجرایی Cloudflare Worker، شناسهٔ گروه‌ها، webhook، مسیر ارسال عکس گروهی
و تنظیم Nginx تغییر نکرده‌اند. این نسخه migration جدید ندارد و دیتابیس، رسانه
و `.env` عملیاتی را جایگزین نمی‌کند. اصلاحات ایمنی ویرایش، حذف، تطبیق قیمت و
جلوگیری از ارسال دوبارهٔ نامشخصِ پچ قبلی همچنان برقرار هستند.

## اعمال روی local

این مراحل پس از دسترسی به کامپیوتر انجام می‌شوند. ابتدا مبنا و تغییرات
ثبت‌نشده را بررسی کنید:

```powershell
git status --short
git log -1 --oneline
git apply --check .\zad-studio-reconcile-5821425.patch
```

مبنای بررسی‌شده `5821425` در شاخهٔ `fix/studio-safety` است. اگر کد local بعد از
آن تغییر کرده یا بررسی patch خطا داد، قبل از اعمال، همان تفاوت باید بررسی شود.
فایل دانلودشدهٔ patch می‌تواند untracked باشد.

پس از موفقیت بررسی و حفظ هر تغییر قبلی:

```powershell
git switch -c fix/studio-reconcile
git apply .\zad-studio-reconcile-5821425.patch
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test --noinput
node --test ops/cloudflare/zad-telegram-relay-worker.test.mjs ops/tests/studio-actions.test.cjs
git diff --check
```

خروجی migration باید `No changes detected` باشد. پچ دانلودشده را داخل commit
کد قرار ندهید. ثبت و push پس از بررسی نتیجهٔ local انجام می‌شوند.

## تطبیق VPS

آرشیو کد فعلی VPS در ۳ اکتبر دریافت و مقایسه شد. مبنای سرور `86e058b` در شاخهٔ
`deploy/studio-team-bddf3a7` است و working tree گزارش‌شده تمیز بود. اصلاح تأخیر
۴۵ دقیقه‌ای در `7750c83` و اصلاح فرم در `86e058b` ثبت شده‌اند. پچ مخصوص VPS از
همین آرشیو ساخته می‌شود و این دو اصلاح را حفظ می‌کند.

بستهٔ نهایی دو پچ با یک نتیجهٔ مشترک دارد: پچ local برای `5821425` و پچ VPS
برای `86e058b`. کد اجرایی Worker و تمام فایل‌های مدل و migration در آرشیو سرور
با نسخهٔ نهایی یکسان بودند. تنها تفاوت stylesheet عمومی، یک خط خالی انتهای
فایل بود؛ نسخهٔ نهایی همان پایان فایلِ سرور را حفظ می‌کند.

با دسترسی به ترمینال، از `/var/www/zad/app` ابتدا فقط خروجی‌های زیر دریافت
می‌شوند:

```bash
git status --short
git log -8 --oneline
sudo systemctl is-active zad.service zad-studio-deliveries.service
```

پیش از اعمال پچ VPS باید همچنان HEAD برابر `86e058b` و کد پروژه تمیز باشد.
بررسی اولیهٔ سازگاری:

```bash
git apply --check /home/cloud-admin/zad-studio-reconcile-vps-86e058b.patch
```

اعمال پچ و بارگذاری سرویس‌ها، پس از پشتیبان‌گیری تازه و بررسی نسخهٔ local
انجام می‌شوند. یکسانی فایل‌های کد هدف است؛ تفاوت تاریخچهٔ commit یا
تنظیمات محیط local و production دلیل جایگزینی کل پروژه نیست. از اعمال پچ قدیمی
با `--reject`، reset اجباری، انتقال دیتابیس local و بازنویسی پوشهٔ media پرهیز کنید.

پیش از استقرار نهایی، نسخهٔ قابل‌بازگشت کد و پشتیبان تازهٔ دیتابیس و رسانه حفظ
می‌شوند. پس از بررسی سازگاری، اجرای check و collectstatic، هر دو سرویس وب و
پردازشگر باید کد جدید را بارگذاری کنند؛ restart وب به‌تنهایی کافی نیست. زمان
این مرحله با کار تیم هماهنگ می‌شود. ارسالِ درحال‌اجرا یا نتیجهٔ نامشخص را به
صورت دسته‌جمعی دوباره صف نکنید.

برای تشخیص تنظیمات و شمارش صف، فرمان زیر فقط می‌خواند و درخواست شبکه ندارد:

```bash
/var/www/zad/venv/bin/python manage.py studio_delivery_check
```

در نسخهٔ جدید، مقصد خصوصی `admin=disabled` گزارش می‌شود. حتی بررسی شبکهٔ مقصد
خصوصی در این حالت به تلگرام درخواست نمی‌فرستد. پس از استقرار، سلامت سرویس‌ها
و رفتار اولین تراکنش واقعی تیم بررسی می‌شود؛ محصول ساختگی روی VPS ثبت نمی‌شود.
بازگشت احتمالی، بازگشت کد است؛ بازگرداندن دیتابیس قدیمی درحالی‌که تیم محصول
ثبت می‌کند بخشی از این مسیر نیست.

## شواهد بررسی

مجموعهٔ ۵۸۸ تست Django با یک تست skipped و ۵۲ تست JavaScript موفق بودند.
بررسی سیستم، نبود تغییر migration و پاک‌بودن diff نیز تأیید شدند. رفتار تأخیر
۴۵ دقیقه‌ای، حذف مدیریتی فوری،
حفظ backoff جدید در تغییر هم‌زمان، بازیابی صف پس از restart، عدم انتشار دوباره،
خاموش‌ماندن صف خصوصی قدیمی و اعتبارسنجی نوع تولید پوشش داده شده‌اند.

بررسی مرورگر در عرض‌های ۳۷۵، ۳۹۰، ۷۶۸ و ۱۴۴۰ پیکسل روی دیتابیس و رسانهٔ
مستقل انجام شد. انتخاب اجباری نوع تولید، تایپ و اصلاح قیمت، بازیابی پیش‌نویس،
حفظ اطلاعات پس از خطای ارسال و ثبت موفق با همان پیش‌نویس، تأیید و لغو حذف و
تاریخچهٔ فقط‌خواندنی اعلان خصوصی بررسی شدند. اعتبارسنجی فرم بدون JavaScript
نیز بررسی شد. محیط آزمایش پردازشگر ارسال یا اعتبارنامهٔ تلگرام نداشت.
این بررسی جای مشاهدهٔ PostgreSQL و ارسال واقعی پس از
تطبیق و استقرار کنترل‌شدهٔ VPS را نمی‌گیرد.
