# بسته مجله و سئوی محتوایی زاد

این بسته روی کد main با پایه `9ca636a2923c86fdb6ee61a12ec0d6960b834fbb` ساخته شده است. تغییرات روی سایت زنده اعمال نشده‌اند. هدف: کمک به انتخاب گل و تبدیل خواننده به گفت‌وگوی سفارش، با پیوندهای مرتبط و قابل مدیریت.

## محتویات

- هشت مقاله کامل فارسی در `main/content/editorial_launch.json` با عنوان سئو، توضیح متا، پاسخ کوتاه، تیتر، مقایسه، پرسش‌وپاسخ و پیوندهای مرتبط.
- صفحه فهرست با دسته‌بندی موضوعی و صفحه‌بندی؛ صفحه مقاله با فهرست قابل کلیک، جدول، تصویر، منابع و دعوت به هماهنگی.
- مدیریت بلوک‌ها، محصولات منتخب با دلیل ارتباط، دسته اصلی و مطالب مرتبط در ادمین.
- پیوند برگشتی از محصول و دسته به مقاله‌هایی که عمداً به آن‌ها مرتبط کرده‌اید.
- پیش‌نمایش خصوصی برای مدیر دارای اجازه ویرایش، حذف مقاله آینده از فهرست عمومی و سایت‌مپ، داده ساختاریافته Article.
- ورود امن پیش‌نویس‌ها و گزارش آمادگی بدون انتشار خودکار.

## نصب محلی (PowerShell، داخل پروژه با venv فعال)

ابتدا تغییرات فعلی را نگه دارید و `git status --short` و `git log -1 --oneline` را ببینید. اگر پروژه جلوتر از پایه است، فقط در صورت عبور از check ادامه دهید؛ از reset یا force برای تحمیل پچ استفاده نکنید.

```powershell
git apply --check .\zad-editorial-final-9ca636a.patch
if ($LASTEXITCODE -ne 0) { throw 'Patch check failed; stop here.' }
git apply .\zad-editorial-final-9ca636a.patch
if ($LASTEXITCODE -ne 0) { throw 'Patch failed; stop here.' }
python -m pip install -r requirements.txt -r requirements-image-upload.txt
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py migrate --plan
python manage.py migrate
python manage.py seed_editorial --dry-run
python manage.py seed_editorial
python manage.py audit_editorial
python manage.py runserver
```

پچ را از ZIP در ریشه پروژه کپی کنید. migration شماره 0031 ساختارهای جدید را اضافه می‌کند؛ متن و آدرس مقاله‌های قبلی را پاک نمی‌کند. اگر پروژه شما migration دیگری با همین شماره دارد، پیش از اعمال باید شاخه‌ها ادغام و وابستگی migration بررسی شود.

هر دستور را جداگانه اجرا کنید و فقط بعد از موفقیت آن سراغ دستور بعد بروید. `seed_editorial` در حالت پیش‌فرض همیشه مقاله جدید را پیش‌نویس می‌سازد و اسلاگ موجود را دست نمی‌زند. در صورت داده نامعتبر، کل ورود rollback می‌شود. `--dry-run` هیچ داده‌ای باقی نمی‌گذارد.

### اگر بسته final قبلی را نصب کرده‌اید

پچ کامل بالا را دوباره اعمال نکنید. فایل `upgrade-from-previous-final.patch` فقط برای نسخه final تحویل قبلی است: ابتدا `git apply --check .\upgrade-from-previous-final.patch` را اجرا کنید؛ فقط در صورت موفقیت، همان دستور را بدون `--check` اجرا کنید. برای نسخه‌های قدیمی‌تر v1/v2 یا هر تعارضی، از force و reset استفاده نکنید؛ ادغام متناسب با وضعیت پروژه لازم است.

برای تازه‌کردن متن‌های دست‌نخورده نسخه final قبلی، فایل `previous-final-content.json` را از بسته کنار manage.py بگذارید و ابتدا دستور زیر را اجرا کنید:

```powershell
python manage.py seed_editorial --update-from .\previous-final-content.json --dry-run
```

گزارش را ببینید؛ سپس همان دستور را بدون `--dry-run` اجرا کنید. فقط پیش‌نویس‌هایی به‌روز می‌شوند که متن، بلوک‌ها، لینک‌ها و ارتباط مقاله‌ای آن‌ها دقیقاً با نسخه قبلی برابر باشد و تصویر داخل بلوک نداشته باشند. مقاله منتشرشده یا ویرایش‌شده حفظ می‌شود؛ عکس جلد، دسته و محصولات متصل حفظ می‌شوند. متن موارد SKIP را در صورت نیاز با `articles-fa.md` مقایسه کنید. پیش از تغییر داده از دیتابیس نسخه پشتیبان بگیرید.

## آماده‌سازی هر مقاله در ادمین

1. در بخش مقاله‌ها، پیش‌نویس را باز کنید و از پیوند پیش‌نمایش خصوصی استفاده کنید.
2. تصویر واقعی متناسب با متن را برای جلد انتخاب کنید؛ تصاویر داخل متن باید توصیف دقیق داشته باشند. از تصویر محصول دیگری به‌عنوان نمونه همان مدل استفاده نکنید.
3. در صورت ارتباط، دسته اصلی را انتخاب کنید. این کار مقاله را در همان صفحه دسته و محصولات آن معرفی می‌کند.
4. دو تا چهار محصول واقعی مرتبط را انتخاب و دلیل ارتباط هرکدام را وارد کنید؛ تعداد کمتر ولی مرتبط بهتر از پرکردن تصادفی است. متن‌ها بدون اتصال محصول نیز قابل خواندن‌اند.
5. قیمت و موجودی را فقط در محصول اصلاح کنید. برای مدل سفارشی، هماهنگی زمان و هزینه لازم است؛ برای ارسال روز، موجودی و زمان تأیید می‌شود. مقاله وعده ارسال تضمینی یا موجودی قطعی نمی‌دهد.
6. عنوان، متن و لینک‌ها را مرور کنید؛ منبع و پیشنهاد تصویر در `docs/editorial-sources.md` آمده است. نام بازبین را فقط پس از بازبینی واقعی ثبت کنید.
7. در موبایل و دسکتاپ پیش‌نمایش را بررسی کنید، سپس وضعیت را منتشرشده و تاریخ واقعی انتشار را تنظیم کنید. تاریخ آینده یعنی عدم نمایش عمومی تا آن زمان.

## راهبرد محتوایی و پیوندها

مالک نیت «سفارش گل در مشهد» صفحه `/mashhad/flower-order/` است. مقاله «سفارش گل برای مشهد» راهنمای هماهنگی است و به آن صفحه تجاری لینک می‌دهد. برای هر عبارت مشابه یک صفحه تقریباً تکراری نسازید.

مقاله‌ها باید مسئله مشخصی را حل کنند: انتخاب قالب، هدیه تولد، فهم قیمت، تفاوت آماده و سفارشی، رنگ، سفارش از راه دور، مشاهده چیدمان و نگهداری. پیوند مقاله به مقاله فقط برای ادامه منطقی مطالعه است. محصولات با تغییر موجودی نباید سبب حذف URL مقاله یا تبدیل مقاله به فهرست تبلیغ شوند.

عکس و توضیح واقعی محصولات مزیت اصلی زاد است. متن این بسته قیمت، موجودی، نظر مشتری یا تجربه اجرای ساختگی ندارد. نام محصول را بعداً بر اساس خود تصویر و مدل واقعی بنویسید؛ کد شناسه داخلی باقی بماند.

## اندازه‌گیری

رویدادهای مقاله از لایه موجود `zadAnalytics` استفاده می‌کنند؛ فعال‌بودن تنظیمات آنالیتیکس پروژه پیش‌نیاز مشاهده آن‌هاست. تعریف رویدادها در فایل JS همراه بسته مشخص است. کلیک تلگرام فقط شروع ارتباط است، نه سفارش قطعی؛ تعداد سفارش‌های واقعاً نهایی‌شده باید توسط تیم فروش ثبت شود.

در Search Console صفحه و عبارت را با دوره قبلی مقایسه کنید، نه فقط رتبه میانگین کل سایت. صفحات مقاله و صفحه سفارش را جدا ببینید. مقاله را وقتی داده یا نیاز واقعی جدید دارید اصلاح کنید؛ تغییر مصنوعی تاریخ، تکرار کلمه و تولید صفحات مشابه هدف نیست.

## انتقال به VPS

پس از تست محلی و ثبت نسخه، از کد، دیتابیس و رسانه نسخه پشتیبان تأییدشده بگیرید. پچ روی همان پایه بررسی شود. سپس با `/var/www/zad/venv/bin/python` دستورهای check، migrate --plan، migrate، seed_editorial --dry-run، seed_editorial و collectstatic --noinput را در `/var/www/zad/app` اجرا کنید؛ بعد سرویس را restart و وضعیت و صفحات را بررسی کنید. فایل `.env`، رسانه و تنظیمات Nginx را این بسته جایگزین نمی‌کند.

بازگرداندن کد پس از انتشار به‌تنهایی داده را برنمی‌گرداند. migration برگشتی جداول مقاله را حذف می‌کند؛ بدون بکاپ و تصمیم روشن روی داده، migrate به 0030 اجرا نکنید.
