## اجرای طرح تأییدشده

- پوستهٔ روشن کرم، منوی سرمه‌ای، فونت فارسی محلی و تأکید نارنجی.
- پیشخوان با میان‌برهای مبتنی بر مجوز، کارت‌های مدیریت صفحات و فعالیت‌های واقعی خود کاربر.
- دسته‌بندی منو: محصولات، صفحات، استوری‌ها، درخواست‌ها، تنظیمات و آرشیو تنظیمات قدیمی.
- فهرست محصول در موبایل به کارت تبدیل می‌شود؛ جستجو، فیلتر، مرتب‌سازی و انتخاب گروهی حفظ می‌شوند.
- فرم‌های استاندارد Django/Jazzmin و تفکیک کاتالوگ عمومی، ارسال روز و عروسی حفظ می‌شوند.
- نوار ذخیره در موبایل، راهنمای وضعیت آخرین ذخیره، اخطار خروج با تغییرات ذخیره‌نشده.
- پیش‌نمایش محلی فایل تصویر قبل از ذخیره؛ اعتبارسنجی و پردازش رسانه همچنان سمت سرور است.
- منوی موبایل با Escape، بازگرداندن فوکوس و محدودشدن فوکوس به منوی باز؛ حرکت‌های ۱۶۰ تا ۲۲۰ میلی‌ثانیه و رعایت reduced motion.
- برای خوانایی متن دکمهٔ نارنجی تیره است؛ برای محتوای واقعی فرم‌ها از جایگزینی با اطلاعات نمایشی ماکاپ استفاده نشده است.

## یافته‌ها و تصمیم‌ها

| بخش | وضعیت و اقدام |
| --- | --- |
| قالب‌های اختصاصی ادمین | مسیر قالب پروژه بعد از Jazzmin انتخاب می‌شد؛ اولویت موتور قالب اصلاح شد و خروجی واقعی قالب‌ها تست شد. |
| متن صفحات، ورکشاپ، بلاگ | حذف مخفی‌سازی از تنظیمات، CSS و mixin؛ منو همچنان تابع مجوز Django است. |
| PageContentBlock | فهرست معتبر صفحه/بخش در `main/admin_content.py` ثبت شده؛ ترکیب جدیدِ بی‌اثر رد می‌شود. رکوردهای قدیمی بدون حذف یا پاک‌شدن مقادیر قابل نگهداری‌اند. |
| فیلدهای هر بلوک | راهنما مشخص می‌کند کدام فیلد واقعاً مصرف می‌شود. sort_order ترتیب بخش‌های ثابت صفحه را جابه‌جا نمی‌کند. |
| متن ورکشاپ | فرم روی سه فیلد مصرف‌شدهٔ برنامه‌های آینده متمرکز شد؛ فیلدهای قدیمی در دیتابیس حفظ می‌شوند. |
| HomeHeroSlide | در گروه تنظیمات قدیمی همراه توضیح عدم اتصال به Home فعلی باقی می‌ماند؛ تصاویر قدیمی خودکار دوباره فعال نشده‌اند. |
| SiteHero ورکشاپ | فقط اولین تصویر دسکتاپ/موبایل مصرف می‌شود؛ فرم این محدودیت را توضیح می‌دهد. |
| دسته‌بندی‌ها | نام و تصویر و وضعیت متصل‌اند؛ ترتیب بعضی دسته‌های شناخته‌شده در Flowers توسط منطق فعلی ثابت است. رفتار عمومی تغییر نکرد. |
| مناسبت‌ها | تصویر و وضعیت متصل‌اند؛ عنوان بعضی اسلاگ‌های شناخته‌شده از نگاشت ثابت می‌آید. فرم توضیح دارد. |
| محصولات | لینک مشاهده و دسته/حوزه/انتشار/موجودی بر اساس رکورد واقعی در فرم نمایش داده می‌شود. نمایش در نتایج به دسته و فیلتر صفحه هم وابسته است. |
| تصاویر محصول | از طریق inline محصول مدیریت می‌شوند؛ مدل تکراری مستقل همچنان از منوی اصلی مخفی است. |
| اطلاعات تماس و آدرس | همچنان تنظیمات محیط اجرای سایت هستند؛ این پچ مدل جدید تنظیمات تماس ایجاد نمی‌کند. |

هیچ تصویر یا رکورد موجود، مدل یا migration تغییر نکرده است. این پچ همهٔ متن‌های ثابت سایت را به CMS تبدیل نمی‌کند؛ سطح کنترل فعلی را قابل پیدا کردن و شفاف می‌کند و از ثبت جایگاه جدیدِ بدون اتصال جلوگیری می‌کند.

## شواهد بررسی

۳۴ تست شامل پیشخوان، فرم‌های اصلی، کاربر محدود، فرم فقط‌خواندنی، ورود صحیح/ناموفق، تأیید حذف، ذخیره واقعی متن تماس و مشاهده در صفحه عمومی، حفظ دادهٔ قدیمی، محدودهٔ محصولات و رگرسیون صفحات عمومی پاس شد.
`manage.py check`، `makemigrations --check --dry-run` و بررسی نحو دو فایل JavaScript پاس شد.

تأیید بصری و اجرای تعامل‌های JavaScript در مرورگر انجام نشده است: مرورگر محیط برای آدرس محلی `ERR_BLOCKED_BY_CLIENT` برگرداند. رندر HTML و تست Django جایگزین تأیید بصری موبایل نیستند.

## بررسی نهایی روی لوکال

در عرض‌های ۳۶۰، ۳۹۰، ۷۶۸، ۱۰۲۴ و ۱۴۴۰ پیکسل:

1. ورود، باز/بسته‌کردن منو، Escape و جابه‌جایی عرض هنگام بازبودن منو.
2. فهرست محصولات: جستجو، فیلتر، مرتب‌سازی و انتخاب گروهی؛ بدون اسکرول افقی کل صفحه.
3. ویرایش محصول آزمایشی: عکس، قیمت و موجودی، ذخیره، نمایش خطای اعتبارسنجی در تب مربوط.
4. فرم تصویر و inlineها، تب‌های طولانی، بازشدن صفحه‌کلید موبایل و دسترسی به نوار ذخیره.
5. متن تماس آزمایشی: ذخیره از پنل و مشاهده در سایت؛ غیرفعال‌کردن باید متن پیش‌فرض را برگرداند.
6. با Reduce Motion روشن، پنل باید بدون انیمیشن کار کند.

برای اعمال روی لوکال ابتدا `git apply --check` و سپس اعمال پچ، بررسی Django و تست ادمین را اجرا کنید. پس از تغییر settings سرور محلی را دوباره اجرا و مرورگر را کامل refresh کنید. برای انتشار واقعی، staticها باید طبق روند استقرار پروژه collectstatic شوند؛ این پچ خودکار چیزی را deploy یا push نمی‌کند.
