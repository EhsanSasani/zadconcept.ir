# بهبود کشف محصولات و صفحات فروش زاد

## رفتار نهایی

- صفحات دسته‌بندی گل، سوئیت‌بار، هدیه و صفحات «همه محصولات» پس از ۴۸ محصول متوقف نمی‌شوند. پیوندهای HTML صفحهٔ بعد و قبل، فیلتر انتخابی را حفظ می‌کنند. صفحهٔ دومِ بدون فیلتر canonical مستقل دارد؛ فیلترها همچنان noindex هستند و آدرس‌های خارج از محدوده ۴۰۴ می‌دهند.
- دادهٔ ساختاریافتهٔ CollectionPage و ItemList دقیقاً محصولات همان صفحه و همان ترتیب نمایش را توصیف می‌کند؛ مجموع قیمت یا امتیاز ساختگی اضافه نشده است.
- صفحات دسته‌گل، باکس، بوکت و جار گل عنوان و توضیح فارسی متناسب با انتخاب و سفارش در مشهد دارند. راهنمای خرید شامل پرسش‌های قیمت، انتخاب مدل و هماهنگی ارسال و لینک به مسیرهای واقعی سفارش است. این بخش فقط در صفحهٔ اولِ بدون فیلتر نمایش داده می‌شود.
- عنوان اصلی صفحات کاتالوگ با بنر بدون عنوان حذف نمی‌شود. چهار مجموعهٔ معتبر عروسی از تنظیمات واقعی برنامه وارد sitemap می‌شوند.
- برای تصویر پویای پوستهٔ استوری ابعاد پایه ثبت شده است؛ این عنصر ابتدا مخفی است و این تغییر به‌تنهایی اثبات بهبود CLS نیست.

## آدرس محصولات و موجودی

آدرس canonical محصول هنگام تغییر دسته ثابت می‌ماند و نام مستعار مبتنی بر شناسه به همان محصول ریدایرکت می‌شود. محصولات آمادهٔ فروخته‌شده، کشیده‌شده، پیش‌نویس یا غیرفعال با این انتشار دوباره عمومی نمی‌شوند. نمونه‌های ۴۰۴ بررسی‌شده شامل محصول آمادهٔ فروخته‌شده و آدرس بدون رکورد مطابق بودند؛ ریدایرکت حدسی به محصول دیگر یا صفحهٔ اصلی ساخته نشده است.

## بررسی

- تست صفحه‌بندی با ۴۹ محصول، بدون تکرار بین دو صفحه؛ حفظ فیلتر و canonical؛ تطابق schema با محصولات قابل مشاهده؛ عدم افشای پیش‌نویس و آمادهٔ فروخته‌شده.
- تست عنوان اصلی با بنر خالی و دارای عنوان؛ metadata فارسی؛ حضور هر چهار مجموعهٔ عروسی در sitemap؛ ابعاد تصاویر در حضور استوری.
- بررسی لوکال: ۱۴۰ صفحه، ۱۴۸ لینک داخلی، صفر خطا و صفر هشدار.
- بررسی واقعی مرورگر در عرض‌های ۳۹۰ و ۱۳۶۵ پیکسل، بازکردن پرسش‌های راهنما و رفت‌وبرگشت بین صفحات محصولات.
- مجموعهٔ کامل Django: ۸۳۸ تست شناسایی شد؛ نتیجهٔ نهایی OK با یک skip. هر ۴۵ تست Worker نیز پاس شدند. check، بررسی نبود migration جدید و migrate --plan بدون خطا بودند.
- تغییر مدل و migration ندارد. رسانه‌های تولیدی و آپلودشده بخشی از بستهٔ انتشار نیستند.

گزارش‌های آماری خصوصی Search Console و خروجی‌های خام بررسی در محیط کار مالک نگهداری می‌شوند و جزو این بستهٔ کد نیستند. درخواست مجدد خزش یا تأیید رفع خطا در Search Console فقط باید پس از تأیید نتیجهٔ انتشار انجام شود؛ noindexهای عمدی و ۴۰۴های واقعی به‌صورت دسته‌جمعی «رفع‌شده» اعلام نشوند.

## سنجش پس از انتشار

پاسخ صفحات اصلی، عنوان‌ها، canonical صفحهٔ دوم، پیوندهای صفحه‌بندی، وجود مجموعه‌های عروسی در sitemap و دسترسی به CSS جدید بررسی شوند. سپس گزارش‌های جست‌وجوی عبارت‌های محلی در بازه‌های یکسان مقایسه شوند؛ میانگین جایگاه کل سایت یا کلیک را نباید معادل رتبهٔ یک عبارت خاص یا تعداد سفارش فرض کرد.

امتیاز سرعت یا رشد رتبه تضمین نشده است. Search Console دادهٔ کافی Core Web Vitals نداشت؛ درخواست PageSpeed از API با ۴۲۹ و در مرورگر با ۴۰۳ رد شد، بنابراین عددی برای سرعت ادعا نمی‌شود.
