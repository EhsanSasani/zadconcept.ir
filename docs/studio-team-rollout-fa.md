# پنل تیم زاد — راهنمای اجرای محلی

این پچ روی نسخهٔ Studio UI v2 ساخته شده است (مبنای کد: `eac8108`، همراه migration `0036_florist_profile_photo`). ابتدا روی شاخهٔ محلی بررسی شود. این تحویل به معنی استقرار روی VPS نیست.

## قابلیت‌ها

- ورود اختصاصی `/studio/login/`؛ پنل شخصی فلوریست `/team/` و داشبورد مدیریت `/studio/`.
- حساب فلوریست به پروفایل موجود وصل می‌شود؛ سازندهٔ محصول از فهرست فلوریست‌های فعال انتخاب می‌شود. هیچ فردی در فرم تازه از قبل انتخاب نشده است و انتخاب سازنده ضروری است.
- دوربین/گالری، پیش‌نمایش و تعویض عکس، قیمت فارسی، فاکتور واقعی، پیش‌نویس روی همان دستگاه، نمایش پیشرفت و تلاش مجدد.
- محصول روزانه بلافاصله در ارسال روز سایت قرار می‌گیرد؛ محصول سفارشی فقط در دفتر تولید ثبت می‌شود.
- عکس، قیمت و شماره فاکتور از سایت به گروه آماده‌های موجود ارسال می‌شود؛ نام فلوریست و یادداشت خصوصی ارسال نمی‌شوند.
- ریپلای «فروخته شد» یا «کشیده شد» در گروه، محصول را از ویترین خارج می‌کند؛ دفتر تولید و تصویر باقی می‌مانند. پیام خروجی ربات حذف می‌شود؛ اگر قدیمی یا حذف‌ناپذیر باشد، کپشن با وضعیت جدید علامت می‌خورد.
- پروفایل همکارها شامل نام، عکس و نمونه‌کار است؛ قیمت، فاکتور، حساب و یادداشت خصوصی نمایش داده نمی‌شوند.
- حساب‌های تیم و صف ارسال در رابط مستقل مدیریت قابل پیگیری‌اند.

## ۱. اعمال پچ در PowerShell

سرور توسعه را متوقف کنید. پوشهٔ پروژه و محیط مجازی فعلی را استفاده کنید. تغییرات کاری قبلی باید قبلاً commit شده باشند.

```powershell
git status --short
git switch -c feature/studio-team-portal
git apply --check .\zad-studio-team-portal.patch
git apply .\zad-studio-team-portal.patch
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test
node --test ops/cloudflare/zad-telegram-relay-worker.test.mjs
git diff --check
```

اگر `git apply --check` خطا داشت ادامه ندهید؛ خروجی همان دستور برای تطبیق نسخه لازم است. پچ شامل فایل‌های UI v2 قبلی نیست.

پیش از migration، از دیتابیس محلی نسخه بگیرید؛ در تنظیمات معمول SQLite:

```powershell
Copy-Item .\db.sqlite3 .\db-before-team.sqlite3
python manage.py migrate --plan
python manage.py migrate
```

migration جدید حساب‌ها، شناسهٔ ثبت یکتا و صف ارسال را اضافه می‌کند؛ حساب خودکار برای فلوریست‌های قبلی نمی‌سازد. وابستگی تازه‌ای به صف خارجی یا سرویس پیامک اضافه نشده است. پشتیبانی HEIC از `requirements-image-upload.txt` موجود پروژه استفاده می‌کند.

## ۲. ورود مدیر و ساخت حساب فلوریست

حساب superuser فعلی می‌تواند در `/studio/login/` وارد داشبورد شود. برای مدیر مستقل از Django Admin:

```powershell
python manage.py studio_account studio-manager --manager
```

رمز در ورودی مخفی ترمینال پرسیده می‌شود. این فرمان مجوزهای استودیو را می‌دهد و `is_staff` را فعال نمی‌کند. حساب موجود رمز خود را حفظ می‌کند، مگر `--reset-password` داده شود.

در داشبورد «حساب‌های تیم» را باز کنید و فلوریست موجود را به نام کاربری اختصاصی وصل کنید. روش خط فرمان هم وجود دارد؛ نمونه برای کد موجود `mz`:

```powershell
python manage.py studio_account mehdi --florist mz
```

برای کد فلوریست واقعی خودتان دستور را تنظیم کنید. حساب عمومی و ثبت‌نام آزاد نداریم. فلوریست در صفحهٔ پروفایل می‌تواند عکس، نام نمایشی و رمز خودش را تغییر دهد. مدیر حساب عادی فلوریست را فعال/غیرفعال یا رمز آن را بازنشانی می‌کند؛ بازنشانی حساب‌های مدیریتی به این نقش واگذار نشده است.

```powershell
python manage.py runserver
```

صفحهٔ ورود: `http://127.0.0.1:8000/studio/login/`؛ ورود فلوریست به `/team/` می‌رود.

## ۳. پیکربندی ثبت روزانه

از مقادیر موجود پروژه استفاده کنید؛ گروه یا ربات تازه لازم نیست:

- `TELEGRAM_SAME_DAY_CATEGORY_ID`: شناسهٔ دستهٔ فعال و عمومی گل در همین دیتابیس.
- `TELEGRAM_SAME_DAY_GROUP_ID`: شناسهٔ همان گروه آماده‌های فعلی.
- حالت relay: `TELEGRAM_SAME_DAY_RELAY_URL` و `TELEGRAM_LEAD_RELAY_SECRET` موجود.
- حالت مستقیم: `TELEGRAM_BOT_TOKEN` موجود؛ وقتی relay تنظیم است توکن در Worker می‌ماند.

شناسهٔ دستهٔ local ممکن است با VPS فرق داشته باشد. بدون دسته یا گروه معتبر، ثبت روزانه با پیام روشن متوقف می‌شود؛ سفارشی‌ها همچنان داخلی‌اند. تنظیمات `.env` پس از تغییر نیاز به راه‌اندازی مجدد سرور دارند.

## ۴. ارسال واقعی تلگرام، پس از بررسی محلی

ثبت محصول هیچ تماس شبکه‌ای با تلگرام نمی‌گیرد. یک پردازش جدا صف پایدار را می‌خواند؛ بنابراین سرور وب تنها، پیام‌های صف را ارسال نمی‌کند.

در حالت relay باید نسخهٔ جدید `ops/cloudflare/zad-telegram-relay-worker.js` ابتدا منتشر شود. مسیر جدید `/studio-delivery` از همان `RELAY_SECRET`، `TELEGRAM_BOT_TOKEN` و `TELEGRAM_SAME_DAY_GROUP_ID` استفاده می‌کند. مسیرهای قدیمی webhook، فایل و lookup حفظ شده‌اند.

پس از آماده‌بودن مقصد، در ترمینال دوم با همان محیط مجازی:

```powershell
python manage.py process_studio_deliveries --watch --interval 3
```

این دستور واقعاً محصولات صف را به گروه تنظیم‌شده ارسال می‌کند. برای صرفاً بررسی ظاهر، اجراکردنش لازم نیست. `Ctrl+C` آن را متوقف می‌کند. `--once` فقط موارد آمادهٔ همین لحظه را پردازش می‌کند؛ جایگزین پردازش دائمی retryها نیست.

تنظیمات پیش‌فرض: مهلت شبکه ۳۵ ثانیه، مهلت پردازش صف ۱۲۰ ثانیه، حداکثر ۶ تلاش برای خطاهای موقت. صف پس از restart باقی می‌ماند.

## ۵. پیگیری ارسال و بازیابی

در `/studio/settings/` به «ارسال محصولات پنل تیم» بروید؛ صفحهٔ مستقل `/studio/deliveries/` وضعیت را نشان می‌دهد.

- قطع ارتباط تلگرام، ثبت قطعی محصول در سایت را از بین نمی‌برد.
- خطای موقت با فاصله تلاش مجدد دارد؛ خطای پیکربندی/دسترسی باید اصلاح شود.
- اگر پاسخ ارسال عکس گم شود، ممکن است پیام واقعاً ارسال شده باشد. وضعیت «نیازمند بررسی پیام در گروه» عمداً ارسال خودکار دوباره ندارد.
- مدیر با بررسی عکس و شماره فاکتور در گروه، شناسهٔ پیام موجود را به همان محصول وصل می‌کند. شناسهٔ عددی پیام آخرین بخش لینک پیام گروه است؛ شناسهٔ گروه را به‌جای آن وارد نکنید.
- اگر پس از بررسی گروه هیچ پیامی پیدا نشد، مدیر می‌تواند در بخش بازشوندهٔ همان مورد، نبود پیام و ارسال دوباره را صریحاً تأیید کند. این اقدام ثبت می‌شود و برای جلوگیری از رقابت با ارسال در حال اجرا، تا پایان مهلت آن پذیرفته نمی‌شود. در صورت رسیدن دیرهنگام پیام قبلی، احتمال تکرار همچنان وجود دارد.
- پیام محصول کمتر از ۴۸ ساعت و با حقوق لازم ربات قابل حذف است. اگر حذف ممکن نباشد، کپشن تغییر می‌کند؛ اگر آن هم شکست بخورد، صفحهٔ پیگیری موفقیت کاذب نمایش نمی‌دهد.
- ورودی قبلی تلگرام در دورهٔ انتقال فعال می‌ماند. کپشن دوخطی خروجی پنل از پارسر چهارخطی ورودی قبلی عبور داده نمی‌شود.

## ۶. آزمون با گوشی

با حساب فلوریست روی گوشی واقعی، عکس دوربین و گالری، HEIC، قیمت فارسی، خطای فاکتور تکراری، قطع شبکه و ثبت پشت سر هم را بررسی کنید. روی گوشی، `127.0.0.1` آدرس کامپیوتر نیست؛ از IP شبکهٔ کامپیوتر و `ALLOWED_HOSTS` مناسب یا محیط HTTPS آماده استفاده کنید. دسترسی دوربین و پیش‌نمایش HEIC به مرورگر بستگی دارد.

پیش‌نویس فقط در همان حساب/مرورگر/دستگاه و تا حد پشتیبانی ذخیره‌سازی مرورگر نگهداری می‌شود؛ پاک‌کردن دادهٔ مرورگر یا خروج از حساب آن را پاک می‌کند. تا تأیید نهایی ثبت، صفحه را باز نگه دارید. آپلود پس‌زمینهٔ تضمین‌شده در iPhone ادعا نشده است. «Add to Home Screen» در Safari برای دسترسی سریع قابل استفاده است؛ صفحه‌های خصوصی در service worker کش نمی‌شوند.

## ۷. مرحلهٔ VPS — هنوز اجرا نشده

پس از تأیید local: backup دیتابیس و media، انتقال commit مشخص، migration، collectstatic، انتشار Worker هم‌نسخه، restart سرویس وب و راه‌اندازی سرویس جدا برای `process_studio_deliveries --watch`. اطلاعات `.env` و media جدا از کد حفظ شوند. migration برگشتی صف/اتصال حساب را حذف می‌کند؛ rollback داده باید از backup برنامه‌ریزی شود.

پیش از انتشار عمومی ورود، محدودسازی درخواست در proxy یا cache مشترک تنظیم شود؛ محافظ سادهٔ ورود این نسخه با LocMemCache بین workerهای Gunicorn مشترک نیست. آزمون مرورگر خودکار جای آزمون نهایی دوربین و کیبورد iPhone واقعی را نمی‌گیرد.

## ۸. نتیجهٔ بررسی و commit محلی

تست‌های این تحویل: ۴۸۲ تست Django با نتیجهٔ موفق (یک مورد skip)، ۲۹ تست Worker موفق، بررسی schema و migration و `git diff --check` بدون خطا. مرورگر در عرض‌های ۳۷۵، ۳۹۰، ۷۶۸ و ۱۴۴۰ بررسی شد. ثبت روزانه/سفارشی، بازیابی عکس پس از reload، خطای ۵۰۳، توقف ارسال، خطای نشست ۴۰۱ و گرفتن CSRF تازه، ثبت بدون JavaScript، پاک‌شدن پیش‌نویس پس از خروج و ورود مدیر بدون دسترسی Admin آزموده شدند. هیچ پیام واقعی تلگرامی در این آزمون‌ها ارسال نشد. تست دوربین/کیبورد iPhone واقعی و هم‌زمانی PostgreSQL روی VPS همچنان در مرحلهٔ پذیرش باقی‌اند.

پس از بررسی محلی و پیش از مرحلهٔ VPS، فایل پچ دانلودشده را از پوشهٔ پروژه بیرون ببرید و فقط کد را commit کنید:

```powershell
git add .env.example config/settings.py main ops/cloudflare/zad-telegram-relay-worker.js ops/cloudflare/zad-telegram-relay-worker.test.mjs docs/project/06-studio-team-contract.md docs/studio-team-rollout-fa.md
git diff --cached --stat
git commit -m "Add florist portal and site-first product publishing"
```

## تغییر انتخاب فلوریست — ۱۴۰۵/۰۷/۰۸

در ثبت محصول پنل تیم و داشبورد، گزینهٔ نخست «فلوریست را انتخاب کنید» است. پنل تیم اجازه می‌دهد برای هر فلوریست فعال محصول ثبت کنید. سازنده در `florist` و حساب واقعی ثبت‌کننده در `created_by` نگهداری می‌شود. جزئیات و کارهای ثبت‌شده برای همکار برای ثبت‌کننده هم قابل مشاهده است؛ آمار تولید فقط به سازندهٔ انتخاب‌شده تعلق دارد. دسترسی به رکورد سایر همکاران همچنان از صفحهٔ نمونه‌کار با اطلاعات محدود انجام می‌شود.

انتخاب فرد در پیش‌نویس ذخیره می‌شود؛ شروع یک محصول تازه دوباره انتخاب خالی دارد. انتخاب غیرفعال در درخواست تازه پذیرفته نمی‌شود و تلاش مجدد پس از ثبت نمی‌تواند سازندهٔ رکورد قبلی را عوض کند. این تغییر migration جدید ندارد.
